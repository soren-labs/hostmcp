# PR #10 review and regression validation

Date: 2026-11-04. Reviewed starting revision: `b907cbc`.
Integrated code revision: `6a5170e`; the subsequent documentation commit does
not change executable code. This record describes local validation; GitHub CI
results are attached to [PR #10](https://github.com/soren-labs/hostmcp/pull/10).

## Findings addressed

| Finding | Reproduction against the earlier implementation | Correction |
| --- | --- | --- |
| Request context cancellation did not interrupt blocked network I/O | Real TCP partial-body and unread-response tests still held their slots after 2 seconds with a 150 ms request deadline | Cancel-time read/write deadlines; stop or join the callback before returning the handler |
| Legacy MCP tool contexts detached the HTTP deadline | Both 2025-06-18 and 2025-11-25 tool calls retained a slot until the test released the executor | Carry the absolute admission deadline through SDK context values and restore it at dispatch |
| Ping write timeout could lose its cause | A controlled WebSocket transport reproduced the generic closed-network error | Join the heartbeat before returning the connection error |
| Ordinary Hub shutdown could be called a heartbeat failure | A GoingAway/maintenance close during Ping produced the wrong heartbeat diagnosis | Preserve normal WebSocket close and shutdown reasons |
| Non-PTY exec returned on its first banner | Short commands and same-request-ID retries reported running before their requested wait elapsed | Wait for completion, yield expiry or a full output budget; retain interactive first-output behavior |

The new regressions were first run against the earlier implementation and failed
as expected. They then passed with their corresponding fixes. The review also
strengthened the subscription test: a 200 response alone is insufficient, so it
now checks static capabilities, a real acknowledgement, and completion. A
separate real SDK subscription test deliberately enables notifications and
verifies deadline-driven cleanup.

## Additional follow-up decisions

- Configuration reuse is a **parsed-policy cache**, not a TTL or disk-read cache.
  Every call reads and permission-checks the current file; only exactly equal
  bytes reuse decoding and validation. Every returned snapshot deeply owns its
  nested grants. Tests cover cross-Store atomic revocation, equal-size edits with
  restored timestamps, malformed/missing/insecure/oversized files, concurrent
  callers and aborted Update callbacks. No read or validation error falls back
  to cached authorization.
- Both MCP result representations remain intentional. The
  [MCP structured-content recommendation](https://modelcontextprotocol.io/specification/2025-06-18/server/tools#structured-content)
  and the pinned Go SDK use a JSON text fallback for clients that do not consume
  structured content. Wire-level tests check both representations, large integer
  precision, Unicode and partial failures.
- Normal non-PTY exec waits until completion or yield expiry. PTYs and
  `write_stdin` keep their first-output behavior; a full return budget yields
  early. Zero yield remains immediate, and cancellation stops waiting without
  killing an already-started command or consuming its unread output.

## Scope and limits

- The HTTP deadline includes body reception and Hub result waiting after
  admission. It cancels context-aware handlers and supported network I/O; it
  cannot preempt arbitrary Go code that ignores cancellation.
- An expired request detected before dispatch does not send a command. A result
  timeout after dispatch retains the unknown-outcome semantics, leaves the Agent
  connected, and does not kill the already-started operation.
- Authorization changes affect subsequent fresh reads; an in-flight check that
  already read the previous file is not retroactively revoked. This matches the
  previous uncached behavior.
- The blocked-I/O tests use real HTTP/1 TCP connections. HTTP/2 stream-level
  deadline behavior was checked against Go's implementation, not exercised by
  a new multi-stream integration test here.
- These results do not establish long-term availability or universal GUI-client
  compatibility. No release tag or release publication is part of this review.
